# 上下文治理二轮修复与验收

**本次上下文专项通过**，本机已切换到 `CONTEXT_STRATEGY=layered`、`CONTEXT_PRUNING_TIMING=pressure`。通过范围是冻结参数场景和真实业务接口；不代表全项目其余检索/生产质量门禁均已通过。

## 正确性与成本分开验收

原计划开发108次、留出252次，共360次已完成。原始留出保留BLOCK：发生网络异常，另有B组一次工具JSON参数错误，以及C组一次明确“价格超出当前预算”被旧评分词表误判。按预先登记规则完成21次A/B/C整组网络恢复复核；原答案、失败和逐行来源均保留。明确原因同义复核采用统一规则，21项正反例通过，不改原始评分器结果。

|完整正确性恢复分析|通过/运行|
|---|---:|
|legacy|84/84|
|deterministic|83/84|
|layered|84/84|

最终审计发现，旧计量绕过了SDK结构化摘要调用，因此**旧开发、主留出及网络恢复报告中的token缺少摘要，不能用于宣称成本达标**。修复底层真实请求计量后，另做6个长场景×A/C×3次，共36次独立复核；每次24轮选购加1轮验收续答、两次整理、一次数据库恢复，逐条检查summary usage。它与原360次属于不同实验，不混合汇总。

完整长对话实际输入下降 **35.85%**，包含摘要（含候选校验重试）及回查后的模型调用。按场景聚合重复、配对bootstrap的95%区间为 **33.30%～38.85%**。普通轮P95比值C/A **0.979**；压缩轮、整段会话耗时单独报告。共享网关实验结果不冒充生产流量P95。

开发集入口有损35/36、使用后36/36、压力触发36/36。两个安全策略正确率相同，开发完整成本因摘要漏计未知；按照预先确定的“证据不足默认压力触发”规则选pressure，不使用不完整token排序证明更优。

## 主要修复

- 商品回查支持字段组、明确字段列表及价格/库存组合；SKU身份与报价绑定，非默认SKU不套用默认SKU到手价。历史数据和当前状态严格区分。
- 只折叠完全重复描述；同次输入中的完全相同商品共享完整业务对象，保留每批顺序、条件和时间，不修改数据库原始证据或页面历史。
- 摘要校验读取同买家/会话的原始证据，正确识别合法SKU。失败候选不能成为事实来源；受控重试失败后恢复最后有效状态。
- 同句选中和排除分别处理，“改选”替换旧选择；回顾或核对问句不再覆盖容量、颜色、数量、预算和选择，明确修改仍生效。
- 沿用AgentScope 2.0.6原生结构化生成，补齐其底层请求的预算、共享限流、实际usage和取消清理。格式错误也计成本，未知usage不记零。
