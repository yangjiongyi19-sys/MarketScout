# 历史会话恢复修复与验收 · 2026-09-18

本次已修复并验证历史会话重开、完整原文恢复和运行记录恢复。网页已恢复使用默认买家 `pao-coder` 与工程 `data/`；该账号原有 7 段会话逐段浏览器验证通过。验收前后 13 次运行的投影及状态哈希完全一致，没有改写原历史。

## 发现与修复

| 问题 | 处理 |
| --- | --- |
| 本浏览器刚创建的会话尚未进入服务端目录缓存，切回来只加载 localStorage | 在 AG-UI 模式下每次打开已知历史都查询数据库；重复打开支持失败重试，快速切换拒绝迟到响应 |
| 后端会话投影、前端解析都只恢复最后 100 条消息 | 从数据库各轮最终投影按顺序合并、按消息 ID 去重，兼容已有数据；模型输入继续使用最多 100 条的权威工作窗口 |
| 长历史恢复后继续聊天，SDK 快照可能再次覆盖早期页面原文 | 保留工作窗口之前的原文，窗口内部仍整体替换，避免将流式草稿与最终回答重复合并 |
| 旧商品只保存在早先运行，最新轮次没有商品时无法查看 | 增加只读“历史商品记录”，保留当时顺序、SKU、价格、库存、配送国家；不冒充当前搜索结果，不提供交易按钮 |
| 运行记录重新打开后为 0 | 从数据库恢复最近 80 条事件元数据，仅返回 ID、类型和已有时间，不返回工具参数或推理内容；无时间的旧事件不编造时间 |
| 会话目录超过 100 段后，旧会话被静默隐藏 | 目录返回该买家的全部轻量会话条目，正文仍按点击会话单独读取 |
| 日常启动被旧的 Prompt 工具合同固定版本阻塞 | 将当前源码导入为不可变版本，并只更新本机 `.env` 的 `PROMPT_PIN_VERSION`；未改发布基线、旧版本和既有会话分组 |

本机版本调整见 [local-prompt-pin.json](local-prompt-pin.json)，启动前原始报错见 [normal-startup-before-fix.log](normal-startup-before-fix.log)。当前固定版本与上一轮真实澄清工具浏览器验收使用的源码版本一致；这里没有做自动发布或灰度放量。

完整历史读取仅使用既有运行日志，不通过摘要模型“还原”原文。当前待审批状态仍来自最新运行，不从旧轮次复活已处理审批。表单仍从表单数据库读取最新版，避免用 AG-UI 旧快照覆盖已提交答案。

## 重现方式与边界

- 后端：项目根目录执行 `GLOBEX_REDIS_SERVER_BIN=<本机redis-server路径> .venv/bin/python -m pytest -q`。
- 前端：`cd frontend` 后执行 `npm test`、`npm run build`。
- 本次浏览器脚本：[隔离恢复](verify_browser.py)、[原账号只读复核](verify_normal.py)。脚本中的会话 ID 属于本机本次验收数据，迁移环境时需替换，不能冒充通用测试数据。受控长会话生成过程见 [seed_history.py](seed_history.py)，只允许对隔离数据目录使用。
- 验收端口为后端 8000、前端 5174；完成后已撤掉进程级测试买家和测试数据目录覆盖，恢复项目本机配置。
- 外部 embedding 网关仍返回 HTTP 200 空响应，商品向量建库降级。历史恢复不依赖该服务，本轮没有宣称修复该外部依赖，也没有重新评估检索或模型推荐质量。
- 恢复依赖数据库文件仍存在；删除运行日志后的原文无法由此机制凭空重建。执行记录在页面展示近期摘要，数据库原始日志继续保留。
